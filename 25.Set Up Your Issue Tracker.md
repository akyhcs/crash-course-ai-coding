# Set Up Your Issue Tracker

## Steps To Complete

### 1. Install and Authenticate the GitHub CLI

The GitHub CLI is how the agent is going to communicate from your local setup to GitHub to fetch the issues.

* [ ] **Install the GitHub CLI**

Visit [cli.github.com](https://cli.github.com/?utm_source=chatgpt.com) to find installation instructions for your platform.

* [ ] **Run `gh auth login` to authenticate**

```bash
gh auth login
```

You'll be prompted to:

1. Choose where you use GitHub → choose **`github.com`**
2. Choose your preferred protocol → choose **`HTTPS`**
3. Choose whether to authenticate Git with your GitHub credentials → **Yes** is recommended
4. Log in with a web browser to complete the process.

* [ ] **Verify your authentication with `gh auth status`**

```bash
gh auth status
```

You should see output showing you're logged in to your GitHub account with an active account status.

Example:

```txt
github.com
  ✓ Logged in to github.com account <your-username> (...)
  - Active account: true
  - Git operations protocol: https
  - Token: gho_************************************
```

---

### 2. Fork the Course Repo

By default, any issues you raise will be against the main version of the crash course repo. Since everyone would be using the same repository, everyone's issues would get mixed together.

So you need to fork the repo to create **your own private copy**.

* [ ] **Run `npx ai-hero-cli fork`**

```bash
npx ai-hero-cli fork
```

* [ ] **Provide a name for your private GitHub repo**

You'll be prompted for a new name for your repo.

You can:

* Use the default name

* Or provide your own name

* [ ] **Confirm the operation**

The CLI will warn you that it is going to:

* Replace this folder's git history with a single fresh commit
* Create a new private GitHub repository

Agree to continue.

Once complete, you'll see a success message with a link to your new private repo on GitHub.

Your previous commands such as:

```bash
git pull
git reset
git cherry-pick
```

will still work.

The important difference is that you now have **your own set of GitHub issues**.

---

### 3. Configure the Repo to Use GitHub Issues

Now you need to configure the repository so the agent knows that **GitHub is your issue tracker**.

* [ ] **Run `npm run reset`**

```bash
npm run reset
```

* [ ] **Search for `setup skills skill`**

This will add the `/setup-matt-pocock-skills` skill to the repository.

* [ ] **Run `/setup-matt-pocock-skills` in Claude Code**

The skill will briefly explore the current state of your repository and provide a recommendation for which issue tracker to use.

* [ ] **When prompted, confirm you want to use GitHub**

Type something like:

```text
yes, GitHub - write both files
```

The skill will then add infrastructure so the agent knows that **GitHub is your issue tracker**.

It creates/updates two things:

#### 1. `AGENTS.md`

It adds an `## Agent skills` section containing a pointer to the issue-tracker documentation:

```markdown
## Agent skills

### Issue tracker

Issues and PRDs live as GitHub issues on <your-username>/<your-repo>, managed with the `gh` CLI. See `docs/agents/issue-tracker.md`.
```

#### 2. `docs/agents/issue-tracker.md`

This file contains the complete conventions for how the agent should interact with GitHub.

For example, it tells the agent how to:

* Create issues
* Read issues
* List issues
* Comment on issues
* Label issues
* Close issues

---

# 4. Test Your Setup

Now verify that everything is working.

* [ ] **Run `/clear`**

Clear the current Claude Code context:

```text
/clear
```

This is important because you want to test whether the agent can discover and use the newly configured issue-tracker instructions from a fresh context.

* [ ] **Ask the agent to add a test issue**

Send:

```text
Add an issue to the issue tracker just as a test, just for a dummy.
```

The agent should:

1. Read:

```text
docs/agents/issue-tracker.md
```

2. See that issues live in GitHub.

3. Use the GitHub CLI.

It should run something similar to:

```bash
gh issue create --title "Test issue (dummy)" --body "Dummy issue created as a test of the issue tracker. Safe to close."
```

* [ ] **Verify the issue was created**

The command will return a GitHub URL.

Open that URL and verify that the test issue exists in **your private repository's GitHub Issues**.

---

# Final Setup

After completing all the steps, your structure should look roughly like:

```text
your-project/
│
├── AGENTS.md
│
├── docs/
│   └── agents/
│       └── issue-tracker.md
│
├── ...
│
└── .git/
```

And the relationship is:

```text
Claude Code Agent
       │
       │ reads
       ▼
   AGENTS.md
       │
       │ points to
       ▼
docs/agents/issue-tracker.md
       │
       │ tells agent
       ▼
   GitHub Issues
       │
       │ accessed through
       ▼
      gh CLI
```

At this point, **GitHub becomes the external place where you store your specs and tickets**, while `AGENTS.md` and `docs/agents/issue-tracker.md` tell the agent **how to interact with that issue tracker**.
